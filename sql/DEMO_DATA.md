# Bengaluru healthcare demo data

`bengaluru-demo-institutions.json` is the offline source ledger for institution names, types, Bengaluru addresses and source URLs. `init-mysql.sql` uses that curated list for a fresh database. The corresponding AI demand CSV is synthetic output generated by `ai-service/ml/generate_demand_dataset.py` and uses a subset of those institution IDs and names.

The seeded institution rows are pending and inactive. No requester/supplier relationship is assigned by the directory seed. A facility can act as a simulated requester or supplier only after the application's own registration and approval workflow; this does not imply that the real institution participates in the project.

Hospital coordinates are deliberately `NULL` in the seed. The backend geocoding flow and administrator map-pin confirmation must supply any coordinates used operationally. The source ledger currently stores no coordinates, so it makes no claim that an approximate map point is an exact institution pin.

Only Rotary Bangalore-TTK Blood Centre (BMST) is included as a blood-bank institution. Its availability and inventory are not seeded. No organ bank or tissue bank is claimed. Organ-related catalog/demand examples refer to simulated transport equipment/resources only; no donor material is represented.

All requests, inventory quantities entered for demonstrations, supplier responses, prices, missions, drone records, routes, telemetry, anomalies, and delivery outcomes are software simulation data. The map's simulated exclusion buffers are not aviation restrictions, legal clearance, or authorization to fly. The project does not control aircraft or transport medical material.

## Existing databases

`migrations/2026-10-06-curate-bengaluru-demo-directory.sql` is a forward-only correction for known old seed rows that are still pending and inactive. It leaves administrator-approved or operational facilities untouched and preserves confirmed coordinates. Review it against the target database before applying it. It is not run automatically and was not applied as part of the source cleanup.

Run the offline validation from the AI service environment:

```bash
pytest -q tests/test_demo_institution_data.py
```
